# Design: GraphQL root lookup gating (#324) and ASCII-only name compare (#317)

## #324

Problem: `nodes` is in `alwaysAllowedFields` so `Connection.nodes` passes. The analyzer looks fields up by name only, so the root `nodes(ids:)` lookup passed too, and any permission-scoped token could read Issue, PullRequest or Discussion bodies through an inline fragment. `node` and `resource` were denied only because no table listed them.

Decision (operator): add a fifth table, `typeConditionScopeRequirements`, that maps a concrete fragment type condition to a read scope. At the operation root (non-mutation), the fields in `rootLookupFields` (`node`, `nodes`, `resource`, `search`) do not use `alwaysAllowedFields` or `fieldScopeRequirements`. At their result position (the field's selection set; for `search`, `nodes` and `edges { node }`):

- each inline or named fragment must have a mapped type condition, and its scope is required;
- fragments with no type condition are transparent;
- only `id` and `__typename` may sit outside a fragment;
- no mapped fragment, an unmapped type condition (including interfaces) or another direct field is unknown, so denied.

Fragment bodies are then walked as ordinary nested selections. The four names stay in the cross-repo tables, so repository-restricted tokens are still denied. The decision sits inside the existing GraphQL analysis, so no new metric stage is added.

## #317

`repoAllowed`, the releases and codeload allow lists, the enterprise exception matcher, the codeload metric labels and the admin list used `strings.EqualFold` or `strings.ToLower`, which apply Unicode rules (`ſ` → `s`, Kelvin sign → `k`). A new package `internal/asciiutil` provides `EqualFold` and `ToLower` that fold A-Z only, and these call sites use it.
