# #293: validate scope permission names at token creation

## Problem

`token.ParseScopeString` checks the level (`read`/`write`) but accepts any
permission name. The docs show `pulls:write`, but enforcement
(`internal/proxy/scope.go`, `internal/proxy/graphql.go`) uses
`pull_requests`. A `pulls:write` token never passes a pull request check. For
`gha_` tokens the map is sent to GitHub's `access_tokens` API unchanged.

## Decision

1. New package `internal/permissions` holds the one canonical list. Both
   `internal/token` and `internal/proxy` import it. The list is the union of:
   - every permission name the enforcement tables use (`scope.go` endpoint
     rules, `graphql.go` field and mutation tables), and
   - the repository and organization permission names of the GitHub App
     permissions object (the names GitHub's `access_tokens` API accepts).
   A test in `internal/proxy` walks the enforcement tables and fails if any
   name is missing from the canonical list, so the two cannot drift.
2. Levels stay `read` and `write`. GitHub's `admin` level is not modelled by
   the proxy (`HasPermission` only understands read/write), so it is rejected.
3. No aliases. GitHub's own API has no `pulls` permission (the App
   permission is `pull_requests`; `pulls` is only a REST path segment), so
   there is nothing to prove an alias against. The docs are fixed instead.
4. Rejection points: `POST /api/tokens` (via `ParseScopeString`), `PATCH
   /api/tokens/{id}`, and the CLI (`ghp token create --scope`, validated
   locally before the request). All return 400 / an error whose message
   lists the valid names.
5. Stored tokens with unknown names are not migrated. They still resolve;
   `parseScopeInfo` logs one warning per unknown name per process.
6. Metric `ghp_token_scope_rejected_total{reason}` with `reason` in
   `unknown_permission`, `invalid_level` (bounded; the name itself is not a
   label). Creation is not part of the proxy decision pipeline, so no new
   `ghp_proxy_decision_duration_seconds` stage.

## Rig

Add `LIFE-293.unknown-scope-name` (`token_api`): POST `/api/tokens` with
`scopes: pulls:write`, expect 400. No `known_issue`.
