# Design: decision histogram buckets and stage docs (#322, #323)

## Problem

`ghp_proxy_decision_duration_seconds` starts at a 50µs bucket. Cheap stages (`scope_enforcement`, `scope_parsing`, `token_extraction`, `border_policy_check`, `forward_proxy_selection`) sit below it at p99, so a regression from 20µs to 45µs is invisible. Two code paths record a hard-coded 0 duration, which skews the histograms low. CLAUDE.md does not list the `graphql_analysis` and `cache_lookup` stages.

## Changes

1. Add 10µs, 25µs, 250µs, 2.5ms and 7.5ms buckets to `decisionBuckets`. Keep every existing bucket so no `le` series disappears. Cost: five extra series per (stage, token_type) pair, bounded.
2. Zero-duration samples. A search for `ObserveDecision(..., 0)` finds two sites:
   - `internal/proxy/proxy.go`, open-scoped GraphQL bypass: recorded 0 for `graphql_analysis` and `scope_enforcement`. Neither stage runs, so the samples are dropped.
   - `internal/proxy/forwardproxy.go`, client-specified proxy: recorded 0 for `forward_proxy_selection`. A selection decision does run, so it is now timed from the start of `ProxyFunc`.
   - The unsafe-path denial cited in #322 already records `time.Since(unsafeCheckStart)` on main; no change.
3. CLAUDE.md and `docs/admin/monitoring.md` gain rows for `graphql_analysis` and `cache_lookup` (monitoring.md also for `forward_proxy_selection` and `enterprise_exception`), a note that stage names are shared across vhosts, and a bucket-change warning.

## Not done: `vhost` label

There are 86 production `ObserveDecision` call sites across `internal/proxy`, `internal/gitcache` and `internal/server`. Most do not have a vhost value in scope. Adding a label means either changing the `ObserveDecision` signature at every site or carrying the vhost on the request context and threading the context into every call, including the forward-proxy `ProxyFunc` and the git cache middleware. Both are wide mechanical changes with a real risk of mislabelled samples, and a label change also breaks every existing dashboard query that aggregates without `sum by`. This is left for a follow-up issue. Until then, operators can split by host with the `backend` label on `ghp_proxy_request_*`.
